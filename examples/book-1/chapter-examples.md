# 第一本範例索引（配套素材，不是章節稿）

本檔每章提供一張簡短操作卡：情境、可直接改寫的請求，以及可檢查的完成條件。教學說明、完整講解、逐步正文不放在讀者服務倉庫。

| 章 | 範例素材 | 完成檢查 |
|---|---|---|
| 1 Codex CLI 是什麼 | 選任務：替純文字待辦程式補測試，或要求代理替你決定公司部署方式。請 Codex 說明哪些工作可先在本機驗證，哪些需人作決策。 | 能區分可委派的程式工作與需政策／人為決定的工作；不把 CLI、IDE、桌面與雲端介面混為一談。 |
| 2 安裝前準備 | 練習前記錄 OS、shell、Git 與 Python 版本；列出你準備操作的專案路徑及是否為 Git 工作樹。 | 記錄實際環境，不依賴其他人的作業系統假設；正式安裝步驟以當期官方文件為準。 |
| 3 安裝、登入與首次啟動 | 安裝後依官方指引確認 CLI 可啟動與版本；登入使用互動式官方流程，不在終端輸出或教材中貼憑證。 | 能看到 CLI 啟動及版本資訊；版本、平台、登入狀態分開記錄。 |
| 4 基本對話 | 以待辦清單為例：先要求「讀檔並描述目前行為，不要修改」；再補上目標、不得改動事項與測試條件。 | 回答指出依據的檔案及假設；尚未授權修改時工作樹不變。 |
| 5 安全專案起點 | 在練習副本確認 `git status --short`、分支及現有差異，再要求 Codex 只檢查 `starter/`。 | 能發現練習前已有變更；不會把原本差異誤認成 Codex 的改動。 |
| 6 第一個修改 | 使用 `examples/book-1/starter/`：只新增待辦新增功能，要求空白內容被拒絕，先提方案後修改。 | 新增與空白輸入均有測試；原有清單內容不被覆蓋。 |
| 7 檢查差異 | 請 Codex 逐檔說明 diff，指出每項變更對應的驗收條件；自行檢視完整 diff。 | 找到意外檔案或無關重構時能要求撤回，而非只看摘要。 |
| 8 測試與失敗 | 執行 README 中的 `python3 -m unittest discover -s starter -p 'test_*.py'`；將失敗 traceback 原文交給 Codex，先要求解釋。 | 能區分預期斷言失敗、語法／匯入錯誤與環境錯誤；修後重跑同一測試。 |
| 9 收尾與復原 | 在副本中做一項刻意不需要的改動，檢視後只復原該檔，再確認 diff 與工作樹。 | 只清除自己確認不需要的練習修改；不使用未理解的廣泛刪除命令。 |
| 10 綜合演練 | 從空資料建立待辦、列出資料、測試空白輸入，讓 Codex 提交變更摘要與未驗證事項。 | 執行結果和驗收條件相符；讀者能指出一項限制及下一個測試。 |

範例提示共通骨架：

> 先檢查指定檔案，不要修改。重述目標、限制、驗收條件及未知假設。待我確認後，做最小必要變更並補測試；完成時列出改動檔案、實際執行的命令與結果、未驗證事項。

Codex 回覆文字由模型生成，沒有固定的預期措辭；應以檔案差異、測試及可觀察行為驗收。

# 第三本範例索引（配套素材，不是章節稿）

本檔提供可套用於個人或團隊工作流程的情境卡，並連到本資料夾的模板。所有與 Codex 指令、設定格式及功能有關的步驟，寫入書稿前都必須依當期官方文件核實。

| 章 | 範例情境 | 操作成果／完成檢查 |
|---|---|---|
| 1 衡量效率 | 對同一類小任務記錄需求澄清次數、人工修正時間、測試結果及返工原因。 | 建立基準表；不以少打字或一次回答成功作為唯一效率指標。 |
| 2 任務提示 | 將「修一下搜尋」改寫為含背景、範圍、驗收、限制與驗證的任務。 | 使用 `task-brief.md`；另一人可據此判斷是否完成。 |
| 3 專案指引 | 為練習專案寫最短一份 `AGENTS.md`：測試指令、檔案慣例、禁止事項。 | 所有規則可驗證且不互相矛盾；依官方文件確認實際載入範圍，不假設範本已生效。 |
| 4 上下文管理 | 將一項功能拆成「檢查／計畫」「實作／測試」「review／收尾」，跨對話交接。 | 交接摘要列出目標、決策、已驗證證據、剩餘項與工作樹狀態；不只貼模型摘要。 |
| 5 權限與沙箱 | 把任務分成唯讀檢查、專案內修改、外部副作用三類。 | 用 `risk-checklist.md` 決定批准閘門；高影響步驟先停下人工確認，不建議以放寬權限換速度。 |
| 6 自動化 | 用一次性、可重跑的小任務檢查範例程式；先設定明確目錄、輸出與失敗處置。 | 命令旗標經當版官方文件核對；非互動流程可辨識非零失敗，且不暗中繼承未確認的模型或權限。 |
| 7 MCP 與外部工具 | 評估新增一個外部資料來源：需要何種資料、是否可寫入、憑證放哪、如何撤銷。 | 留下資料流圖及授權決策；先查來源及官方設定方式，不在範例中放真實憑證。 |
| 8 Skills／外掛 | 評估一個擴充是否可信、必要、維護中，並可否停用。 | 記錄來源、版本、權限、相依與移除方式；只有官方文件已確認的能力才寫成教學指令。 |
| 9 團隊品質閘門 | 團隊任務需經測試、差異審查、機密檢查及人工核可後才可合併。 | 形成責任表；AI 提供的 review 發現要由人與測試驗證，不能直接視為裁定。 |
| 10 成本與模型選擇 | 以相同任務、相同驗收，記錄可用模型選項、耗時、返工與失敗。 | 依當期帳戶與產品條件標註限制；不聲稱單次測試能普遍證明最佳模型。 |
| 11 失敗復盤 | 模擬一次「改錯檔但測試通過」的事件，記錄影響、發現方式與復原。 | 根因區分任務描述、程式修改、測試盲點、權限及環境；新增一個可執行的預防檢查。 |
| 12 個人／團隊工作系統 | 將任務卡、專案指引、風險清單、測試及 review 串成一次小任務流程。 | 另一位讀者能按清單重跑；說明哪些步驟可自動化、哪些保留人工決策。 |

建議記錄欄位：任務識別、執行日期、CLI 版本、作業環境、工作目錄、輸入資料分類、權限決策、改動摘要、實際驗證、人工判斷及未解決事項。不要記錄秘密值或私人資料。
